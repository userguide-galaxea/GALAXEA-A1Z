🦾 硬件概览

⚡ 电机驱动层

最底层，负责将 Python 浮点数编码为 MIT 协议的 64-bit CAN 帧，并将收到的帧解码回物理量。两种电机帧格式不同。

MIT 帧格式对比

MotorA（EC-A4315-P2-36）— 发送帧（64 bits，big-endian）
│ mode(3) │ kp(12) │ kd(9) │ pos(16) │ vel(12) │ torque(12) │

# 反馈帧：
│ report_type(3) │ error(5) │ pos(16) │ vel(12) │ current(12) │ temp_coil(8) │ temp_mos(8) │
# 注意：MotorA 反馈 current（电流），需乘 KT=2.8 换算为 Nm
MotorB（4310 / 4340）— 发送帧（64 bits）
│ pos(16) │ vel(12) │ kp(12) │ kd(12) │ torque(12) │

# 反馈帧：
│ error(4,高nibble) │ pos(16) │ vel(12) │ torque(12) │ temp_mos(8) │ temp_rotor(8) │
# 注意：MotorB 直接反馈 torque（Nm），不需要 KT 换算
⚠️
MotorA 需要 MIT 探测帧才会返回反馈。发 enable 帧（0xFC）后 MotorA 不主动响应，必须再发一条零增益 MIT 指令（kp=0，kd=0.05，torque=0）才能收到位置反馈。MotorB 收到 enable 即回包。

MixedMotorChain — 统一电机链接口

MixedMotorChain 是驱动层的核心。它将 3 个 MotorA + 3 个 MotorB 合并为一个统一的 6 关节接口，ArmRobot 只与它交互，从不直接访问单个电机对象。

# 构造：传入两组电机列表 + 关节下标映射
chain = MixedMotorChain(
    motor_a_list=[MotorA(0x01), MotorA(0x02), MotorA(0x03)],
    motor_b_list=[MotorB(0x04), MotorB(0x05), MotorB(0x06)],
    motor_a_joint_indices=[0, 1, 2],
    motor_b_joint_indices=[3, 4, 5],
)

# 每个控制周期调用顺序：
count = chain.drain_and_update(bus)   # 1. 排空 CAN 接收队列，分发给各电机解析
pos   = chain.get_positions()          # 2. 读取合并后的状态数组（长度 6）
chain.send_commands(pos, vel, kp, kd, torque)  # 3. 广播指令帧

float ↔ uint 定点转换

# utils.py
def float_to_uint(x, x_min, x_max, bits) -> int:
    return int((x - x_min) * ((1 << bits) - 1) / (x_max - x_min))

def uint_to_float(u, x_min, x_max, bits) -> float:
    return u * (x_max - x_min) / ((1 << bits) - 1) + x_min

🧮 动力学层

基于 Pinocchio 的 RNEA（递推牛顿-欧拉算法），每个控制周期计算全逆动力学扭矩作为前馈。

逆动力学公式
τ = M(q)·q̈ + C(q,q̇)·q̇ + g(q)

# 当 q̇=0, q̈=0 时退化为纯重力补偿：τ = g(q)

tau = gravity_model.compute_inverse_dynamics(q, cmd_vel, cmd_acc)
# move_joints() 插值时 cmd_vel/cmd_acc 非零 → 完整逆动力学
# 零力漂浮时 cmd_vel=0, cmd_acc=0 → 纯重力补偿

URDF 选择

动力学模型对 URDF 敏感——末端质量不同，补偿扭矩不同。默认使用 A1Z_Flange.urdf（裸法兰，无末端负载）。

URDF 文件适用场景
A1Z_Flange.urdf默认，裸法兰无末端负载
ℹ️
Pinocchio 在初始化时断言重力向量为 [0, 0, -9.81]，即 base_link Z 轴朝上。若机械臂挂装或倾斜安装，需调用 GravityModel.set_gravity() 修改重力方向。

线程模型

# 两把锁分别保护状态和指令，最小化争用
self._state_lock   = threading.Lock()   # 保护 JointState（读反馈写入）

self._estop_latch  = threading.Event()  # 急停信号（set/clear 原子操作）

get_a1z_robot() — 工厂函数

所有 A1Z 特定的硬件参数集中在 get_robot.py 中，ArmRobot 本身不包含任何 A1Z 特定常数。这使得同一套控制逻辑可支持不同机型。

robot = get_a1z_robot(
    can_channel="can0",
    gravity_comp_factor=1.0,   # 0=关闭重力补偿, 1=全补偿
    zero_gravity_mode=True,    # True=零力漂浮, False=位置保持
    control_freq_hz=250,
)
robot.start()   # 使能电机，启动后台线程
# ... 控制 ...
robot.stop()    # 零扭矩，失能，线程退出

🔄 控制回路（250 Hz）

每个 4 ms 周期执行的步骤，按固定顺序：

1
读取 CAN 反馈 _read_state()
调用 MixedMotorChain.drain_and_update(bus)，排空接收队列，将最新的位置/速度/电流/温度/错误码写入 JointState（加锁）。更新 _last_feedback_t 时间戳。
2
运行时安全检查 _check_runtime_safety()
按顺序：CAN 反馈超时 → 电机错误码 → 温度（MOS + 转子）→ 关节位置限位 → 关节速度限位。任何硬故障抛 RuntimeError，控制回路捕获后调用 disable_all() 并退出。
3
采样示教录制缓冲区
若 _recording=True 且距上次采样已超过采样周期，将当前关节位置追加到 _record_buffer（加锁）。
4
读取当前指令 JointCommand
加 _command_lock 后深拷贝 pos / vel / acc / kp / kd / torque_ff，避免在后续计算过程中被主线程修改。
5
全逆动力学 GravityModel.compute_inverse_dynamics(q, cmd_vel, cmd_acc)
计算 τ = M·q̈ + C·q̇ + g。cmd_vel / cmd_acc 超过硬性上限（±4 rad/s、±20 rad/s²）时直接 raise，不做静默裁剪——因为上游校验已经保证了合规，到这里还超限说明有 bug。
6
合并扭矩 + 帧转换 → 发送
τ_motor = clip((τ_ff + τ_id × scale) × gravity_comp_factor × joint_sign, ±torque_clip)
再调用 MixedMotorChain.send_commands(pos×sign, vel×sign, kp, kd, τ_motor)，将所有 6 个 MIT 帧发送到 CAN 总线。

move_joints() 最小急动度轨迹

# 5 阶多项式（minimum-jerk），在 t=0 和 t=1 处速度、加速度均为零
alpha     = 10*t**3 - 15*t**4 + 6*t**5
alpha_dot = (30*t**2 - 60*t**3 + 30*t**4) / duration
alpha_ddot= (60*t   - 180*t**2 + 120*t**3) / duration**2

cmd.pos = current_pos + alpha * delta        # 位置插值
cmd.vel = alpha_dot  * delta                 # 速度前馈（逆动力学用）
cmd.acc = alpha_ddot * delta                 # 加速度前馈（逆动力学用）
ℹ️
轨迹起点使用上一次发送的指令位置（而非实测位置），避免连续调用 move_joints() 时把 PD 跟踪误差注入为起始跳变。

🛡️ 安全机制

SDK 设计了多层防护，从指令入口到控制周期内均有独立的拦截逻辑。

🔴 急停（ESTOP）

触发条件：连续 5 帧流式指令被拒绝、CAN 反馈超时 0.2 s、电机错误码、MOS 超 85°C / 转子超 90°C、速度超限、关节位置超限（运行时）。急停后 kp→0，kd 减半，重力补偿持续，机械臂不会塌落。调用 robot.release() 恢复。

🟡 警告限速

feedforward vel 上限 ±4 rad/s，acc 上限 ±20 rad/s²（在 _update() 用 assert 而不是 clip）。kp 上限 200，kd 上限 5（在 command_joint_state 入口处拒绝帧）。

🟢 流式指令容错

_clip_joint_pos() 对 ±0.05 rad 以内的轻微越界静默裁剪（1 Hz 频率限制日志）；超出则拒绝当前帧，保持上一条有效指令，不会驱动到几何无关的裁剪位置。

🔵 控制频率监控

每 2 秒统计实际频率，连续 3 次低于 80 Hz（默认）则紧急失能退出。防止系统负载导致控制回路退化到不安全的低频率。

🟢 disable_all() 双发

MixedMotorChain.disable_all() 对所有电机发送两次失能帧（含 10 ms 间隔），应对 gs_usb 总线繁忙时单帧丢包问题，确保电机可靠下电。

🔵 IK 解合理性校验

move_joints(max_jump_rad=) 参数对比当前实测位置与目标之间的距离，拒绝肘部翻转等远离当前形态的 IK 解，防止机械臂扫过整个工作空间。

🚀 快速使用

SDK 的典型使用模式：一切从 get_a1z_robot() 开始，start() 后进入控制，stop() 结束。

零力漂浮（示教 / 遥控）

from a1z.robots.get_robot import get_a1z_robot
import numpy as np

robot = get_a1z_robot(zero_gravity_mode=True, gravity_comp_factor=1.0)
robot.start()

# 读取状态
state = robot.get_joint_state()   # {pos, vel, eff, temp_mos, temp_rotor, error_codes}

# 流式指令（遥控用，单帧失败不中断）
robot.command_joint_pos(target_pos)

robot.stop()

位置保持 + 点到点移动

robot = get_a1z_robot(zero_gravity_mode=False, gravity_comp_factor=1.0)
robot.start()

# 阻塞式平滑移动，内部 5 阶多项式插值，到达后返回
robot.move_joints(
    np.array([0.0, 0.5, -0.3, 0.0, 0.0, 0.0]),
    speed=0.5,        # rad/s（最大关节速度）
    max_jump_rad=0.5, # 拒绝离当前位置过远的目标（防 IK 翻转）
)

robot.stop()

FK / IK 示例

from a1z.robots.kinematics import Kinematics

kin = Kinematics("a1z/robot_models/a1z/A1Z_Flange.urdf")

q = robot.get_joint_pos()
T = kin.fk(q)              # → 4×4 numpy 变换矩阵

# 修改末端位置后求逆解
T_target = T.copy()
T_target[0, 3] += 0.05    # X 方向前移 5 cm

converged, q_sol = kin.ik(T_target, init_q=q)
if converged:
    robot.move_joints(q_sol, max_jump_rad=0.3)
